The audit (snapshots 2026-09-26 02:26–02:44 UTC, `origin/main` @ `20fb576`) listed
15 findings. This page records which ones are fixed in code, the guard test for
each, and the ones that are NOT fixed here — with the reason — so nobody reads
"audit addressed" as "every finding closed".

## Not fixed here — and why

* **Trial lifecycle states (idle/dormant/paused/paid as explicit states, `search_state`, `pause_reason`, per-call dollar reservations, cancel-queued-work).** The one-day meaningful-activity gate above delivers the audit's acceptance scenario ("active on day one, absent → no personalised automatic spend after 24 h; an open tab does not extend it") through the existing single gate (`_user_is_active`, reached by every lane). Explicit states, a visible pause/resume control and dollar reservation need a schema change and UI; not done here.
* **9 — identity migration of 457k unscoped Workday / 5k BambooHR / 26k Teamtailor rows.** `scripts/diagnose_job_identity.py` already dry-runs and repairs in bounded batches; running it against production needs a restorable backup first and is an operator action, not a code change.
* **10 — ingestion quality (first-party preference, job-type classification, per-user unique-eligible metrics).** Product work; the audit itself says not to raise ingestion or caps before 1–3 land.
* **11 — temporary Pro.** `TEMPORARY_PRO_FOR_ALL` is an env flag; turning it on is an operator decision (docs/TEMPORARY_PRO_AND_SUBSCRIPTIONS.md). No code change needed.
* **12 — recruiter research.** Stays on hold, as the audit recommends.
* **14 — acquisition funnel analytics** and **15 — authenticated end-to-end flows (OAuth, recovery, two-account isolation, extension)** need staging accounts and a real browser session; not reproducible from this container.
* **`/api/pipeline/live` p95 9.2 s.** Client polling pressure is reduced (hidden tabs, backoff, no overlap); the route's own queries were not re-measured here. Precomputed per-user counters remain open.

## Limits of this change

Tests are synthetic; nothing here was run against production data. The
re-decision at delivery changes which jobs reach a board from the next
placement onward; existing entries change only when `recheck_eligibility.py
--apply` is run. The one-day window will pause most complimentary accounts
within a day of their last real action — that is the intent, and it is one env
var (`DORMANT_USER_GRACE_DAYS`) to widen.
