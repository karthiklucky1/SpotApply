# Production-readiness audit — 30 Jul 2026

One overnight pass over the whole codebase for security holes, remaining bugs, dead
code and test coverage, before the first 100–150 users arrive.

Method: five specialist agents read the code in parallel (security, correctness,
dead code, test coverage, ops). **Every finding was then verified by hand before
anything was changed** — which mattered, because two of the most alarming ones were
wrong (see [False positives](#false-positives)). Each fix that claims to close a
bug was confirmed against the old code: restore the previous line, watch the new
test fail, restore the fix, watch it pass. Those confirmations are quoted below.

Result: **8 commits, 29 files, +2371/−139**. Test suite went from 691 tests
(1 failing, 35 skipped) to **1031 passing, 6 skipped**, green in both file orders
and with the network disabled.

---

## 1. The headline: CI was red for a reason nobody would have guessed

`jinja2` was never declared in `requirements.txt`, yet `app/api/server.py` builds a
`Jinja2Templates` instance at import time — every page render depends on it. FastAPI
does not pull it in and nothing else in the declared set does either.

Production works **by accident**: `torch` depends on `jinja2`, so the full image
happens to have it. CI installs requirements minus the ML stack on purpose, so there
it was absent and `app.api.server` could not be imported at all — surfacing as four
unrelated-looking test *collection* errors rather than "a dependency is missing."

The consequence beyond CI: any attempt to trim the ~1 GB ML stack out of the deploy
image would have taken the entire app down at startup.

Fixed, plus a CI step that imports `app.api.server` and `app.main` directly (stubbing
only the intentionally-omitted ML stack), so this class of failure reports itself in
one line instead of as collection noise.

## 2. Security

### Unauthenticated cross-tenant access — 7 routes

All seven shared one shape. The handler reads `_get_user_id(request)`, which returns
`None` when unauthenticated, then scopes with:

```python
if uid and uid != "local":
    q = q.where(Model.user_id == uid)
```

That condition **fails open** — `uid is None` skips the filter entirely and the query
runs unscoped across every tenant. It is only safe in a handler that has already
refused the anonymous case.

| Route | What an anonymous caller could do |
|---|---|
| `POST /run/discovery` | Launch a full discovery + match run. `_user_has_resume(None)` falls back to `glob("./data/resume_master.*")` — the founder's own file — so the resume gate passed. Unauthenticated scraper-quota and LLM-budget spend; the 10/min rate limit only slowed it. |
| `GET /api/resume/file` | Download the master résumé off local disk. |
| `DELETE /run/discovery` | Cancel any tenant's discovery run. |
| `GET /api/discovery/last-run` | Read the newest `DiscoveryRun` of **any** tenant. |
| `GET /api/resume/status` | Learn whether the founder's résumé exists, reported as the caller's own. |
| `GET`/`POST /api/profile/avatar` | Push a 3 MB body per request and get a 200. |

The first three were found by hand-review. `/api/discovery/last-run` was missed by
hand-review **twice**, which is the whole argument for what replaced it:
`tests/test_route_auth_inventory.py` walks the app's own route table and requires
every route to be either on an explicit 30-path `PUBLIC_PATHS` allowlist with a
stated reason, or calling a guard that raises. 109 private routes are now checked
mechanically on every run.

### XSS — two dashboard sinks

Server data was interpolated into `innerHTML` unescaped. Company-facts rows now
escape by default with the one anchor row opting into raw HTML explicitly, and the
pending-question label is escaped.

### SSRF guard had no real tests, and the ones near it did real DNS

`/api/public/job-check` fetches a URL supplied by an **anonymous** caller, so
`_is_public_host` is a load-bearing security control — and it was tested only
incidentally. Worse, `tests/test_job_check.py` (whose own docstring says "mocked
HTTP") was doing live DNS on every generic-page test, passing only because
`example.com` happened to resolve to a public address.

It now has deterministic tests with a fake resolver: loopback, all three RFC1918
ranges, cloud instance metadata at `169.254.169.254`, unspecified, multicast, IPv6
loopback and unique-local are each rejected; a host resolving to public **and**
private together is rejected (DNS rebinding); and resolution failure, an empty
answer, and an empty host all fail closed.

### Authorization ≠ authentication

The inventory test proves a route refuses anonymous callers; it cannot prove the
route checks *who* is asking. A second sweep now requires every route taking a
resource id to check ownership. **This one found nothing** — all 20
`/application/{id}/*` routes already use `_require_owned_application`, and
notifications, profile memory, intros and job-verify all compare the row's owner to
the requesting uid. It locks in current behaviour rather than fixing a hole.

## 3. Correctness bugs

### An unverified résumé was reported as grounded

`app/tailoring/grounding.py` imports `sentence_transformers` at module level, and
`tailor.py` constructed `GroundingChecker` inside a bare `except Exception` that only
logged a warning and left `grounding_failed = False`. So on any deploy where the ML
stack is absent or the model download fails, every tailored résumé was written with
`"grounding_passed": true` — claiming an anti-hallucination check that never read a
single bullet.

The untested path and the silently-broken path were the same one: without torch the
import raises, which is exactly what CI does.

Grounding now has three states — passed, failed, **never ran**. "Never ran" reports
`grounding_status: "unverified"`, logs at ERROR (it is an infrastructure failure, not
a clean résumé), and puts a warning on the application telling the user to read every
bullet against their own résumé. The draft is still delivered, because the human
review + Submit step is the design's backstop and failing closed would turn a
transient ML hiccup into a total outage of the core feature — but a backstop only
works if the human is told. `GROUNDING_REQUIRED=1` opts into blocking instead. Either
way, "passed" is never reported for a résumé that was not read.

The Tailoring Studio surfaced no grounding state at all, only the doctor score; it
now shows a badge for each state and reveals Rebuild for the two that are not a
clean pass.

> Confirmed: restoring the old one-line report field fails the new test with
> *"a résumé whose grounding check never ran was reported as having passed it."*

### Work authorization: "citizens only" ≠ "citizens or permanent residents"

These are different legal bars and the code collapsed them — wrongly in **both**
directions. Reading "Green Card" as citizenship admitted permanent residents to real
ITAR/cleared roles; reading it as non-citizenship rejected them from the far more
common postings that explicitly accept permanent residents.

Citizenship and permanent residency are now resolved separately on both sides, and PR
only counts when the posting itself accepts it. Verified across a 15-case matrix; the
two phrasings plus the negated-status case (`"not a us citizen"`) are pinned.

### Account deletion left data in 14 tables

`DELETE /api/account` named 7 tables by hand while the schema has 18 with a `user_id`
column, because tables kept being added after the route was written — the CardRace
tables were only the most recent.

The route now enumerates `SQLModel.metadata`, with an explicit `_EXTRA_OWNER_COLUMNS`
map for the three intro/message tables that key on other columns. An enumeration
cannot fall behind the schema the way a hand list did. Also added a guard the old code
lacked: `SHARED_POOL_USER` owns the pool every tenant is served from, so "delete my
account" for that identity would have wiped the corpus for everyone — now a 400.

> Confirmed: restoring the old 7-table list fails the new sweep, naming every
> survivor — `userpersonalmemory, trialgrant, recruiterprofile, candidateintro,
> intromessage, introrating, trusthistory, user_referral_reward, user_notifications,
> llm_spend, user_card, card_match_shadow, coupon_redemption, user_review`.

### `cards.py` — three cache-correctness bugs (module had zero tests)

1. **Stale profile facts, the one with user-visible consequences.** `resume_hash`
   covered only the LLM prompt, but a UserCard also carries deterministic facts, and
   `card_match`'s work-auth and location factors read from *those and nowhere else*.
   So a user who got a green card, changed preferred country, or flipped
   remote/relocation kept a cached card carrying the old facts and went on being
   gated by them **indefinitely** — their résumé text had not changed, so nothing
   ever triggered a recompile. The facts are now in the cache key while staying out
   of the prompt, and one `profile_facts()` helper feeds both so they cannot drift.
2. **Version invalidation was missing on both readers** — bumping `JOB_CARD_VERSION`
   or `USER_CARD_VERSION` (which you do precisely when the shape changes) kept
   serving old-shape payloads forever, and would have quietly mixed schemas in the
   shadow agreement data the calibration gates are judged on.
3. **`uid = user_id or "local"`** mapped every None-owner job onto the local/founder
   UserCard row — the shape of the ARCHITECTURE §7.1 founder-résumé leak, in a new
   module, reachable because NULL-owner `Job` rows exist. Now fails closed.

> Confirmed: restoring the previous `resume_hash` fails 8 of the 23 new tests.

### Index DDL in three places, disagreeing

`_PERF_INDEXES` re-created `ix_job_user_closed` on **every startup** — the index the
Jul 29 maintenance runbook had just dropped — so each deploy burned a multi-minute
`CREATE INDEX CONCURRENTLY` on 764k rows and undid the fix. Meanwhile the two indexes
that *resolved* that incident existed only in `models.py`, so they were never created
on the live database. `tests/test_index_declarations.py` now pins all three DDL sites
against each other, and `db_maintenance --fix-indexes` only drops indexes that are
INVALID.

### Smaller ones

- **Dashboard reload loop.** The 5-day shortlist freshness filter went into the SSR
  render only, so `/api/pipeline/live` still counted stale rows. The client reloads
  whenever the empty state renders while the server reports a non-zero count — an
  infinite 30-second reload. Both now share `_shortlist_fresh_clause()`.
- **Stale-unscored expiry** now uses `coalesce(posted_at, first_seen, discovered_at)`
  so rows missing `posted_at` aren't treated as infinitely old, batches the UPDATE,
  keeps NULL-owner rows out of the shared-pool exemption, and logs failures at
  WARNING.
- **CardRace input hardening.** JobCard fields are LLM output: numeric coercion is
  tolerant (`"5+"` years, `"high"` importance), skills may arrive as bare strings, and
  country comparison goes through `geo.norm_country` on both sides — raw equality
  scored a flawless US candidate for a US role at 10 (a hard blocker) and the old
  substring test matched `"us"` inside `"australia"`.
- **Egress.** `pipeline.py`'s frozen-score reset streamed every matched posting's full
  description to null out two fields. Now projected.
- **Stale compiled CSS.** `.w-52`/`.w-64` were missing from `app/static/tailwind.css`,
  so three search inputs rendered with no width constraint. Rebuilt.

## 4. Test suite

### It was order-dependent

Green alphabetically, **red in any other order**.
`test_scoring_lane_starvation.py` set `_deferred_until[1] = now + 3600` and never
cleaned up; SQLite then reused row id 1 in `test_scoring_lane.py`, whose jobs the
lane skipped as "deferred" — two failures visible only in that file order.

Rather than fix the instance, `conftest.py` now resets **every** process-global
counter and cache after each test (scoring-lane deferrals and attempt counts,
reranker budget/breaker/usage state, card mint accounting, the résumé cache), and the
leaky test uses sentinel ids that cannot collide with a real row. CI runs the suite a
second time in reversed file order.

### 25 tests were skipped forever

The ATS/DOCX suite was guarded by `skipif(not settings.resume_path.exists())` and
`data/resume_master.md` is gitignored — so 25 tests covering **the artifact users
actually send to employers** (ATS-safe DOCX, no tables or text boxes, required
sections, action-verb bullets, banned phrases, cover-letter length) ran on a laptop
and nowhere else. Turning a red build green by deleting the coverage is the wrong
trade before launch.

They needed no committed artifact at all. The fixture already wrote its own résumé
and patched `app.tailoring.tailor.settings`; what it missed is that `tailor.py`
resolves the master through `app.matching.pipeline._load_resume`, which reads the
**real** `settings.resume_path`. Patching that makes all 23 self-contained. Same fix
for `test_tailoring.py`, whose file-level skip also covered a test that never needed
a résumé.

Separately, conftest's ML skip matched the substring `"test_grounding"`, sweeping up
pure-Python files — so the anti-hallucination suite ran nowhere in CI. Narrowed to
the two files that genuinely build a real checker.

### New coverage

| File | What it pins |
|---|---|
| `test_route_auth_inventory.py` | Every route consciously public or guarded; ownership on id-bearing routes |
| `test_grounding_enforcement.py` | The grounding **gate** (all three states + strict flag), not just the detector |
| `test_cards.py` | Cache versioning, identity, mint cap, budget backstop, cross-tenant key |
| `test_account_deletion.py` | Zero rows left, second tenant intact, schema-driven |
| `test_billing.py` | Webhook verification, plan resolution, grace boundary, no secret leaks |
| `test_architecture_invariants.py` | The three post-mortems the unit tests don't prevent |
| `test_settings_defaults.py` | The numbers the economics rest on, and their lockstep relations |
| `test_index_declarations.py` | Three DDL sites can't disagree |

`test_architecture_invariants.py` deserves a note. Each of the three incidents has a
good tested helper *and* a post-mortem, and the gap is the same every time: the
helper works, but nothing stops new code from not using it. So it asserts every
Playwright launch sits inside `browser_slot`, `SentenceTransformer`/`CrossEncoder`
are constructed only in `matcher._MODEL_CACHE`, and no hot path does a whole-entity
`Job` read. That last check is AST-based, not grep — a line match cannot tell prose
in a docstring from `select(Job.id)` from `select(Job).options(load_only(...))`, and
only the unprojected form is what the 205%-of-egress-quota incident was about. It has
a self-test proving the detector still detects.

`test_settings_defaults.py` exists because every other test injects its own
thresholds, so the **defaults** were asserted nowhere: set `shortlist_max_age_days` to
90 and the whole suite stays green while the board starts showing month-old postings.
The lockstep relations matter as much as the values — scoring never reaching further
back than the board renders, the Tier-1 gate tracking the shortlist bar, the global
cap staying above 50 Pro users' worth of finals so it can't quietly become the real
allocation again.

### CI

Was: install, blocking lint on `E9,F63,F7,F82`, `pytest --maxfail=5`, template

## 5. One decision flagged, not made

**Turning on Stripe is a cliff.** `_get_user_plan` returns PRO for everyone while
Stripe is unconfigured — correct pre-revenue, since there is nothing to buy — but no
existing user has a `user_subscription` row. So the second `STRIPE_SECRET_KEY` and
`STRIPE_PRICE_ID_PRO` are set, **every existing user silently drops to FREE**: 50 → 15
finals/day, unlimited → 5 tailors/day, unlimited → 2 autofills/week. No warning, no
action on their part, on the exact day you start charging the user base you spent
months acquiring.

Both sides of the flip are now asserted so it is a known decision rather than a
surprise, and `PLAN_GRANDFATHER_UNTIL` (an ISO date, **empty by default so behaviour
is unchanged**) keeps pre-launch signups on PRO. It fails closed on an unset or
unparseable date — never hand out PRO by accident.

The webhook itself was already correct: it refuses with no secret and raises on a bad
signature. It had simply never been tested, and an unverified webhook is a
free-upgrade vulnerability, so it is pinned now.

## False positives

Both were serious-sounding and both were wrong. Worth recording, because verifying
before fixing is what kept them out of the tree.

- **"12 of the `/application/{id}/*` routes check neither ownership nor auth."** All
  20 call `_require_owned_application`. The agent's static analysis missed the helper.
- **"Ownership missing on notifications / profile memory / intros / job verify."** All
  four compare the row's owner to the requesting uid; my own first grep missed them
  too, because they use `!=` and a 404 rather than `==` and a filter.

## Still open

Ranked. Nothing here is a live vulnerability; these are the next things worth doing.

1. **Per-user token budget for interactive features.** The nine uncapped LLM routes
   now carry rate limits (`tests/test_llm_route_limits.py` lists all 16 spending
   routes and requires one on each), but slowapi keys on **IP** — that is a burst
   guard, not a quota. Finals are metered per user per plan; on-demand routes are
   not. Also still open: `/api/fill-pack/{id}` bypasses the tailor cap, and
   `score_final` is never recorded in `LlmSpend`, so per-user attribution
   undercounts.
2. **Recruiter self-verification.** A recruiter marks themselves verified, and
   verification is what unlocks candidate search. Worth a manual gate before the
   recruiter side is promoted.
3. **No CSP, unpinned CDN scripts, refresh token via `postMessage`.** The dashboard
   loads Chart.js and Cropper from jsDelivr without integrity hashes.
4. **Ops visibility.** No `/readyz`, no Sentry DSN set, no alerting channel. Right now
   a lane dying silently is invisible until the board looks stale.
5. **`WEB_CONCURRENCY>1` has no fail-safe.** Every lane would run once per worker.
6. **`first_seen IS NULL` backfill** — those rows are excluded from the freshness
   windows entirely.
7. **Card mint single-flight.** Concurrent workers can mint the same JobCard more than
   once; correct, just wasteful.
8. **`funnel_events`** has no retention, no `user_id`, and an N+1 in `get_summary`.
9. **`_RESUME_CACHE` grows unbounded** (15-min TTL, no eviction).
10. **`test_registry_maintenance.py` is 20 s of real sleeps** — 54% of suite runtime
    before tonight's additions.
